# Карточки грузовых шин

Отдельный рендерер `truck_card.py` использует фон `assets/truck-tread-background-v1.png` и те же файлы шрифтов, что легковые карточки. Компактный верхний блок: бренд 94, модель 62, размер 128 на рабочем холсте 1200×1600; JPEG по умолчанию 900×1200. Перед характеристиками оставлен увеличенный зазор. Шина крупная, с обрезкой снизу/справа, если позволяют пропорции фото.

```bash
python truck_card.py source.jpg --data product.json --output preview-output/truck.jpg
```

Минимальный `product.json`:

```json
{
  "brand": "Goodride",
  "model": "CR926",
  "size": "7.50R16",
  "application": "Универсальная",
  "ply_rating": "14 PR",
  "construction": "Радиальная",
  "equipment": "TTF",
  "load_index": "122",
  "speed_index": "L"
}
```

Обязательны `brand`, `model`, `size`. Остальные поля отображаются только при наличии; пропущенные характеристики не заменяются выдуманными значениями или пустыми плашками. Картинка должна быть **исходным фото шины**, не готовой оформленной карточкой. Рендерер подключён к API через `product_type: "truck"`, `theme: "dark"` и к общему редактору `/cards/viewer` с выбором типа товара. API дополнительно требует `sku` и `image_url`. Примеры — в [API-INTEGRATION.md](API-INTEGRATION.md#тип-товара-легковые-и-грузовые). Обработчик фида пока генерирует только легковые карточки.

Формат размера для грузовой карточки не ограничен легковой схемой. Скрипт пробует выделить диаметр по `R`, `ZR`, дефису/тире или отдельному числу в конце (`11R22.5`, `18.4L-26`, `12-16.5 NHS`, `10.5/80 18`). Неизвестные обозначения сохраняются, а не пересчитываются. Если диаметр неоднозначен, вся строка показывается целиком без отдельной плашки — товар не пропускается. Можно передать отдельное поле `diameter`, тогда оно используется явно. Проверка размера в легковом API от этого не меняется.

Пять примеров из предоставленных Ozon-карточек сохранены локально в `preview-output/ozon-truck-batch/index.html`. Фотографии из них вырезаны по явно заданной области — общего автоматического распознавания старых рекламных макетов нет. Разрешение исходных фото шин внутри этих карточек низкое; увеличением резкость не восстановить.

Общий `cutout` теперь дополнительно удаляет крупные однотонные нейтральные области внутри шины, включая светло-серые (от 220). Это геометрическая эвристика, а не распознавание предметов: небольшие блики сохраняются, но необычное фото с большим ровным светлым диском нужно проверить. Для программного отключения: `cutout(path, remove_holes=False)`. Существующие карточки сами не изменяются — требуется перегенерация.

Для вырезания товара из уже оформленной карточки можно передать в `cutout` заранее обрезанный `PIL.Image`. Чужие рекламные надписи, цены и налоговые обещания не переносятся.
