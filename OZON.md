# Загрузка карточек в Ozon

В `.env` в корне `/opt/product-card` добавьте свои значения:

```dotenv
OZON_CLIENT_ID=ваш_client_id
OZON_API_KEY=ваш_api_key
```

Файл должен читаться пользователем `productcard`. После изменения настроек: `sudo systemctl restart product-card`. Ключу Ozon нужны права на чтение товаров/фотографий и изменение изображений. Ключи в браузер не передаются.

Откройте `/cards/viewer`, найдите или сгенерируйте карточку и нажмите «Загрузить на Ozon». Публикуется последнее сохранённое изображение выбранного типа и темы, а не несохранённые поля формы. К артикулу поиска добавляется `SU`: `S272362` → `S272362SU` (Ozon `offer_id`). Локальные артикулы и имена файлов не меняются.

Порядок работы:

1. `/v3/product/info/list` находит `product_id` по `offer_id`.
2. `/v2/product/pictures/info` получает главное фото, дополнительные фото и образец цвета.
3. Исходные фотографии скачиваются в `<CARD_OUTPUT_DIR>-ozon-backups/<идентификатор>/`; там же сохраняются прежние ссылки. Если скачивание не удалось, импорт не запускается.
4. `/v1/product/pictures/import` получает полный список: **сгенерированная карточка, памятка хранения, прежние фото с третьего по последнее**. При 0–2 прежних фото передаются только две новые картинки. Образец цвета сохраняется отдельно.

Памятка: `assets/tyre-storage-guide.jpg`. Это приложенный оригинал, преобразованный в JPG. Снимки отправляемых изображений лежат в `<CARD_OUTPUT_DIR>/ozon-publish/` и доступны по `/images/ozon/<идентификатор>/card.jpg` и `guide.jpg`. Не удаляйте их во время обработки Ozon. Архивы исходников занимают место; удаляйте старые вручную после проверки результата.

Статус «Ozon принял запрос» означает приём импорта, а не завершение обработки/модерации. При потере ответа проверьте карточку в кабинете перед повтором; автоматического повторного импорта нет.

Генерация и отправка в интерфейсе выполняются фоновыми задачами; браузер опрашивает `/cards/viewer?job_id=...`. Используйте **один worker Uvicorn**. Задачи и их статусы живут в памяти процесса; при перезапуске API проверьте результат перед повтором. Прежний синхронный API генерации сохранён.

Для внешнего клиента: `POST /api/v1/cards/{sku}/ozon?theme=dark&product_type=truck` с `X-API-Key`. Метод синхронный. Для легковых `product_type=passenger` (по умолчанию). Ссылки сервиса должны быть публично доступны Ozon по HTTPS; `CARD_PUBLIC_BASE_URL=https://tools.3sta.ru`. Существующий маршрут Nginx `/images/` обслуживает новые ссылки.

Если вместо JSON приходит HTML, интерфейс теперь показывает HTTP-код и понятное сообщение. По одному скриншоту нельзя установить точную причину: возможны ошибка/таймаут Nginx или недоступный upstream. Генератор уменьшает крупные исходники до рабочей стороны 1600 перед выделением фона; это снижает расход памяти и время обработки. Для диагностики на сервере:

```bash
sudo systemctl status product-card --no-pager
sudo journalctl -u product-card -n 40 --no-pager
sudo tail -n 30 /var/log/nginx/error.log
```

Описание методов: [получение фото](https://docs.ozon.ru/api/seller/#operation/ProductAPI_ProductInfoPicturesV2), [импорт фото](https://docs.ozon.ru/api/seller/#operation/ProductImportPicturesV2).
