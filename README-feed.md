# Генерация карточек из фида

HTTP API для списка карточек, поиска по артикулу и генерации из JSON описано в [README-api.md](README-api.md).

Скрипт `feed_card.py` читает YML/XML-фид 3sta.ru, выбирает товар, скачивает его первое фото и собирает PNG 1200×1600 в существующем фирменном шаблоне. API генерации изображений и ключи не нужны: используется настоящее фото товара и готовые фоны проекта.

## Запуск

Откройте терминал в папке проекта. Python 3.10+:

```powershell
pip install -r requirements.txt
python feed_card.py --id S207352
```

ID — значение атрибута `id` у `<offer>` в фиде. По умолчанию адрес фида уже задан: https://3sta.ru/yandex/feed.xml.

```powershell
# Первый товар
python feed_card.py
# Первые 10 товаров, только тёмная карточка
python feed_card.py --limit 10 --theme dark
# Первые 10 товаров, обе темы в отдельных папках
python feed_card.py --limit 10 --theme all
# Другой фид или локальный XML
python feed_card.py --feed "https://example.com/feed.xml" --id PRODUCT123
python feed_card.py --feed "feed.xml" --limit 10
# Весь фид — только при явном указании 0
python feed_card.py --limit 0
```

Карточки сохраняются в две папки: `feed-output/dark/<артикул>.png` и `feed-output/light/<артикул>.png`, например `dark/S207352.png`. Артикул берётся из `id` товара в фиде. При `--theme dark` заполняется только тёмная папка; для обеих тем используйте `--theme all` (по умолчанию). Исходное фото `source.img` и все данные `product.json` хранятся отдельно, в соседней папке `feed-output-sources/<артикул>/`. Для другой папки добавьте `--output "D:/cards"` — исходники будут в `D:/cards-sources/`. Повторный запуск перезаписывает файлы этого товара. Карточки, созданные ранее в старой структуре папок, автоматически не перемещаются.

На карточке отображаются бренд, модель, размер, диаметр, индексы нагрузки и скорости, сезон. **Все** поля товара, атрибуты и параметры с единицами сохраняются в `product.json`, включая цену, ссылки, шипы и RunFlat. Они не помещаются на основной макет. Отсутствующие обязательные характеристики вызывают понятную ошибку; скрипт не придумывает значения. Модель берётся из `model`, а при отсутствии — из названия без бренда и размера.

XML обрабатывается потоком и чтение прекращается после выбранного товара или лимита. Поиск ID ближе к концу потребует прочитать предыдущие товары. При пакетной обработке ошибка одного товара не останавливает остальные; код завершения 1 означает, что были ошибки.

Шрифты выбираются автоматически: Arial на Windows или DejaVu Sans на Linux; можно положить DejaVuSans.ttf и DejaVuSans-Bold.ttf в `assets/fonts`. Удаление фона рассчитано на фото с белым однородным фоном. Нестандартное фото или длинное название может потребовать проверки готовой карточки.

Светлая кайма очищается в узкой полосе вдоль края товара с сохранением полупрозрачности. Если фон фото слегка серый и остаётся видимым, попробуйте `--threshold 225` (по умолчанию `235`). Меньший порог удаляет больше светлого фона; на фото со светлыми деталями товара снижайте его осторожно.

## Как изменить оформление

Светлая тема использует `assets/light-paint-background-v8.png`: более чистые широкие фиолетовые и лаймовые мазки без мелких брызг. Тёмный фон не изменён. Старый светлый фон сохранён в `assets/paint-background-v4.png`; его можно выбрать явно: `--background assets/paint-background-v4.png`. Новый фон применяется при следующей генерации, уже сохранённые карточки автоматически не меняются.

Два примера из локальных исходников сохранены в `preview-output/light-v8/`: `S058436.png` (двойной индекс нагрузки `104/102`) и `S058617.png`.

Все шины по умолчанию проходят единый пресет: мягкое выравнивание яркости и контраста и повышение резкости внутри силуэта. Обработка выполняется после масштабирования; маска защищает края, прозрачность сохраняется. Параметры заданы в `finish_tyre()` файла `build.py`. Пресет делает фото более похожими по тону, но не исправляет различия в ракурсе, освещении или исходном разрешении. Для отключения добавьте `--raw-photo` к команде запуска.

Макет задаётся в функции `compose()` файла `banner_card.py` и применяется к обеим темам. Вызовы `text()` задают координаты `(x, y)`, текст, размер шрифта и цвет; `maxwidth` ограничивает ширину и автоматически уменьшает шрифт. Цвета тем заданы переменными `bg`, `fg`, `secondary`, акцентные цвета — `LIME` и `PURPLE`. Фон можно заменить через `--background` и `--dark-background`.

Размер и диаметр расположены рядом: `225/65` обычным текстом, только `R18` на жёлтой плашке. Положение плашки автоматически рассчитывается по ширине размера, зазор — `24` пикселя. Текст начинается на высоте `418`, начальный размер шрифта — `128`; при необходимости оба значения уменьшаются вместе до общей ширины `1068`. После изменения макета запустите скрипт повторно, чтобы пересобрать карточки.
