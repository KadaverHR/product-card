# Экономия места и сжатие существующих карточек

## Ограничения

JPEG — формат с потерями. Повторное перекодирование тоже имеет потери, даже при высоком quality. Выбран компактный профиль по умолчанию: 900×1200, quality 82, 4:2:0 (максимальная сторона 1200). Чтобы лучше сохранить цветные границы текста, задайте subsampling 0; файл станет больше. Для сохранения прежнего разрешения укажите max-edge 1600 явно.

Результаты на одной тестовой карточке, не гарантия для каталога:

| Профиль | Размер | Вес | 180 000 файлов такого веса |
| --- | --- | --- | --- |
| Старый JPG quality 90, 4:4:4 | 1200×1600 | 373 КБ | 67 ГБ |
| Новый JPG quality 85, 4:2:0 | 1200×1600 | 257 КБ | 46 ГБ |
| quality 82, max-edge 1200 | 900×1200 | 155 КБ | 28 ГБ |
| quality 80, max-edge 1000 | 750×1000 | 112 КБ | 20 ГБ |
| quality 78, max-edge 800 | 600×800 | 76 КБ | 14 ГБ |

Это только готовые файлы. Если 180 000 — число товаров и нужны две темы, файлов будет 360 000. ОС, базы, скачанные исходники, PNG-дубликаты и запас для обработки учитываются дополнительно. Диск сервера увеличен до 40 ГБ: для 180 000 компактных файлов оценка составляет около 28–30 ГБ только на карточки, поэтому нужно проверить оставшийся запас. Посмотрите реальные папки: `du -sh /opt/product-card/feed-output /opt/product-card/feed-output-sources` и `df -h /`.

## Сжатие уже готовых JPG на сервере

Сначала обновите код из GitHub после публикации этого изменения. Команды ниже требуют наличия `compress_cards.py` на сервере. Фид повторно не скачивается, карточки не генерируются заново.

Остановите все пакетные генераторы перед обработкой; не запускайте редактор/POST генерации для тех же карточек во время сжатия:

```bash
sudo systemctl stop product-card-feed.service product-card-feed-light.service product-card-feed-dark.service
```

Сообщения о несуществующих задачах допустимы. Не используйте `restart` для генераторов, пока идёт сжатие. Для исключения ручной генерации можно временно остановить `product-card.service`, но это сделает API/редактор недоступными до повторного запуска.

Проверка компактного профиля на первых 100 JPG без изменения файлов:

```bash
sudo -H -u productcard /opt/product-card/.venv/bin/python -u /opt/product-card/compress_cards.py \
  --output /opt/product-card/feed-output --theme all \
  --quality 82 --max-edge 1200 --subsampling 2 --limit 100 --dry-run
```

Настоящее сжатие всех JPG до компактного профиля (уменьшает разрешение больших карточек до 900×1200):

```bash
sudo systemd-run --unit=product-card-compress \
  --uid=productcard --gid=productcard \
  --working-directory=/opt/product-card \
  --property=StandardOutput=append:/opt/product-card/compression.log \
  --property=StandardError=append:/opt/product-card/compression.log \
  /opt/product-card/.venv/bin/python -u /opt/product-card/compress_cards.py \
  --output /opt/product-card/feed-output --theme all \
  --quality 82 --max-edge 1200 --subsampling 2
```

Для сохранения прежнего разрешения укажите `--quality 85 --max-edge 1600 --subsampling 2`. Для ещё более сильного сжатия после просмотра образцов можно выбрать `--quality 78 --max-edge 800 --subsampling 2` (600×800). Компактный профиль и этот вариант уменьшают разрешение: это не «без потерь».

Лог: `sudo tail -n 50 -f /opt/product-card/compression.log`.

Остановка: `sudo systemctl stop product-card-compress.service`. Перед повторным `systemd-run` остановите задачу и сбросьте failed-состояние через `sudo systemctl reset-failed product-card-compress.service`, если оно есть. Сервис может быть уже выгружен — сообщение not found не мешает новому запуску.

### Что делает инструмент

- По одному файлу создаёт временный JPG рядом с исходным, полностью декодирует его для проверки и только потом атомарно заменяет оригинал. Нужен небольшой запас места для одного файла и служебной базы, а не полная вторая коллекция.
- JPG заменяется только если новый файл меньше. Пути `.jpg` остаются теми же; API вернёт изменившийся параметр `v`.
- Прогресс хранится в новой служебной `.card-compression.sqlite3` внутри output. Товарные базы не затрагиваются. При повторном запуске с тем же профилем неизменённые файлы не перекодируются. Удаление этой базы приведёт к повторной обработке и дополнительным потерям качества.
- При ошибке записи оригинал остаётся. Повреждённые файлы фиксируются как ERROR, обработка остальных продолжается. При жёстком завершении процесса может остаться одиночный `.card-*.tmp`; инструмент не удаляет чужие временные файлы автоматически.
- Оригинальная JPG-копия не сохраняется, иначе экономии места не будет. Для возможности отката заранее сделайте резервную копию на другом диске. Уже потерянные детали восстановить нельзя.

## PNG-дубликаты

Обычное сжатие обрабатывает только JPG. `--convert-png` дополнительно создаёт JPG из PNG, но само по себе **не освобождает** место PNG. Существующий JPG при конвертации PNG никогда не перезаписывается.

Если старые PNG-ссылки больше не нужны, можно явно добавить **обе** опции `--convert-png --remove-png`. PNG удаляется только после создания и проверки нового JPG этим запуском. Старые `.png`-ссылки перестанут работать; API будет выдавать `.jpg`. Если JPG уже существовал, PNG сохраняется — нельзя подтвердить, что это одна и та же версия. Такие дубликаты требуют отдельной проверки; автоматического удаления всех PNG нет.

## Новая генерация

Такие же параметры должны использоваться при создании новых карточек, иначе очередная генерация опять запишет большие файлы:

```bash
# Пример компактной генерации, обе темы (900×1200).
sudo -H -u productcard /opt/product-card/.venv/bin/python -u /opt/product-card/feed_card.py \
  --limit 0 --theme all --jpeg-quality 82 --max-edge 1200 --jpeg-subsampling 2 \
  --output /opt/product-card/feed-output
```

Для API задайте в `/etc/product-card.conf` переменные `CARD_JPEG_QUALITY=82`, `CARD_MAX_EDGE=1200`, `CARD_JPEG_SUBSAMPLING=2`, затем перезапустите `product-card.service`. Не копируйте остальные секретные настройки в логи или чат. При отсутствии явных настроек: 82/1200/2. Прежние явно заданные переменные имеют приоритет над новыми настройками по умолчанию.

Исходники в `feed-output-sources` сохраняются отдельно и этим инструментом не удаляются. Кроме того, фид может ссылаться на уже готовую карточку вместо исходного фото — сначала исправьте такие ссылки, иначе генерация создаст «карточку внутри карточки».
