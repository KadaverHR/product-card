# Фиды в проекте карточек

Страница: `https://tools.3sta.ru/cards/feeds`. Переход — из шапки страницы карточек. API и страница работают в той же службе `product-card`; отдельный процесс не нужен.

## Порядок работы

1. Укажите название и публичную ссылку на YML/XML. По умолчанию — `https://3sta.ru/yandex/feed-truck.xml`.
2. Выберите формат: **VK** или **для генерации карточек**.
3. При необходимости задайте точные `offer id` через запятую или по одному на строку. Пустой список — все товары. Суффикс `SU` не добавляется. Неизвестный артикул останавливает сборку.
4. Выберите исходные фото или замену первого фото уже созданной карточкой. Во втором случае укажите тип и тему. Карточки должны существовать для всех выбранных артикулов; остальные фото сохраняются. Тип не фильтрует товары автоматически — он определяет, где искать карточки.
5. Нажмите **Создать новый фид**. В списке появятся ссылка, количество товаров и размер файла.
6. Для обновления откройте параметры существующего фида и нажмите **Пересобрать этот фид**. Источник скачивается заново, ссылка остаётся прежней. Кнопка **Создать новый фид** всегда создаёт отдельную ссылку.

**VK** использует перенесённый из `E:\vk` конвертер `vk_feed.py`: сохраняет товары, категории, цены, ссылки и фото; переводит RUR в RUB; переносит характеристики в описание; удаляет служебный `is_checkout_enabled`; преобразует HTML в обычный текст. Ограничения конвертера: 1–15 000 товаров, результат до 8 000 000 байт, положительные целые цены без округления. Некорректные товары не пропускаются молча. Принятие файла конкретным импортом проверяется в VK.

**Для генерации** сохраняет XML-структуру и характеристики выбранных товаров. Используйте **исходные фото**: генерация из готовой карточки наложит надписи друг на друга. Сборка фида сама изображения не генерирует и товары в VK не загружает.

Исходник — до 32 МБ, YML `yml_catalog/shop/offers/offer`, без DTD/entities. Локальные пути через веб-форму не принимаются. Пустая выборка и дубликаты выбранных ID в источнике останавливают сборку. Относительные ссылки товаров и фото разрешаются относительно URL источника.

## Хранение и Nginx

По умолчанию данные хранятся в `feed-output-feeds/`. При `CARD_OUTPUT_DIR=/path/cards` — в `/path/cards-feeds/`. Папка исключена из Git; сохраняйте её при резервном копировании. Настройки и фиды переживают рестарт. Ошибка не заменяет предыдущую опубликованную версию; версии хранятся в отдельных каталогах.

Постоянная публичная ссылка без ключа:

```text
https://tools.3sta.ru/cards/feeds/files/<feed_id>/feed.yml
```

Страница управления, как существующий редактор карточек, работает без ввода ключа. Фид доступен всем, у кого есть ссылка. В Nginx весь префикс `/cards/` должен идти в Product Card API на `127.0.0.1:8010`. Если был настроен только точный `/cards/viewer`, добавьте в существующий HTTPS server:

```nginx
location ^~ /cards/ {
    proxy_pass http://127.0.0.1:8010;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 180s;
}
```

После изменения: `sudo nginx -t && sudo systemctl reload nginx`. Остальные маршруты и сертификат сохраняются.

## API

Базовый адрес: `https://tools.3sta.ru`. Для всех `/api/v1/feeds` нужен `X-API-Key` сервиса карточек. Nginx должен направлять их в `product-card`, как `/api/v1/cards`.

### Создать

```http
POST /api/v1/feeds
X-API-Key: YOUR_CARD_API_KEY
Content-Type: application/json
```

```json
{
  "name": "Грузовые для VK",
  "source_url": "https://3sta.ru/yandex/feed-truck.xml",
  "format": "vk",
  "offer_ids": ["T587344"],
  "pictures": "original",
  "product_type": "truck",
  "theme": "dark"
}
```

Обязательны `name` (1–120 символов), `source_url`. По умолчанию: `format=vk`, `offer_ids=[]`, `pictures=original`, `product_type=truck`, `theme=dark`. Неизвестные поля запрещены.

- `format`: `vk` или `generation`.
- `pictures`: `original` или `cards` (заменить только первое фото).
- `product_type`: `passenger`, `truck`, `agricultural`, `special`.
- `theme`: `dark`, `light`.
- `offer_ids`: до 15 000 строк длиной 1–100 символов; `[]` — весь каталог.

Ответ запуска, HTTP `200`:

```json
{"status": "running", "job_id": "<job_id>"}
```

Это запуск задачи, а не подтверждение готовности файла.

### Проверить результат

```http
GET /api/v1/feeds/jobs/<job_id>
X-API-Key: YOUR_CARD_API_KEY
```

- `status=running` — выполняется.
- `status=completed` — объект `result` содержит `id`, `url`, `config`, `report`, `created_at`, `updated_at`, `revision`.
- `status=failed` — поля `http_status` и `detail` описывают ошибку. HTTP опроса остаётся `200`: проверяйте `status`.

В `report`: `offers`, `bytes`, `pictures_replaced`; для VK также счётчики заполненных описаний и перенесённых характеристик. Опрашивайте примерно раз в 1–2 секунды. Сборки выполняются по одной; `429` может прийти при запуске или в результате задачи. Статусы задач в памяти теряются при рестарте и очищаются после часа при запуске новых задач; готовые файлы и настройки сохраняются на диске.

### Список и параметры

```http
GET /api/v1/feeds
GET /api/v1/feeds/<feed_id>
```

Нужен `X-API-Key`. Список возвращает `{"items": [...]}`, последние обновления первыми. Каждый элемент содержит настройки, статистику и постоянный `url`.

### Пересобрать

```http
POST /api/v1/feeds/<feed_id>/regenerate
X-API-Key: YOUR_CARD_API_KEY
```

Без тела — сохранённые настройки. Для изменения отправьте полный JSON, как при создании, с `Content-Type: application/json`; частичное обновление не поддерживается. Ответ — новый `job_id`, опрос результата тот же. Ссылка остаётся прежней. При сетевом таймауте/рестарте проверьте список и время обновления перед повторным созданием, чтобы не получить дубликаты.

### Ошибки

`401` — ключ; `404` — нет фида/задачи; `413` — слишком большой исходник; `422` — поля, XML, артикулы, отсутствующая карточка или ограничения конвертера; `429` — занято; `502` — скачивание/сохранение; `503` — ключ API не настроен. Предыдущая версия при ошибке остаётся доступна. Проверяйте также `status=failed` при опросе задачи.

## CLI

Конвертер доступен в проекте карточек:

```bash
python vk_feed.py --source https://3sta.ru/yandex/feed-truck.xml --output feed-vk.yml
```

Сохраняются прежние параметры `--source`, `--output`, `--no-proxy`. Веб-интерфейс не требует запуска CLI вручную. Готовые XML/YML и папки результатов не добавляйте в Git.
